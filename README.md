# 你好，我是 aq 👋

**我在做让 Agent 接入现有软件的框架，也在把航运模型、专业知识和业务流程做成可用的产品。**

我喜欢从一个实际问题出发，一路追到它的实现、数据和使用体验。最近投入最多的是 Agent 工程、航运数据与模型，以及 AI 辅助开发。对我来说，一个功能要能接进系统、用真实数据跑起来，再经得住实际操作中的追问。

## 我正在关注什么

### 让已有软件用上 Agent

我正在开发 [Agenstra](https://github.com/KHG420/agenstra)。目标是让已有前后端系统通过少量适配接入 Agent，把自己的业务接口和能力交给它使用，减少每个项目重复建设工具调用、会话和上下文管理的工作。

我希望用户能通过自然语言查询信息、操作系统、连接不同项目的能力；简单的聊天也能得到自然的回应。框架负责通用的 Agent 能力，业务系统决定自己的规则和界面。

### 把航运知识和模型连接起来

我在推进船舶性能分析、气象航线、航次回溯和专业知识检索相关的工作，会接触 AIS、午报、风浪流、速度与功率曲线、油耗和横摇风险。

我关心模型怎样接进业务，也会追问结果用了哪份数据、字段是什么单位、公式和计算口径是否一致。对专业知识库，我希望它能保留原始资料的含义，让回答有可以核对的依据。

我想逐步沉淀三类东西：**能完成工作的 Agent、可供其他系统使用的 API/MCP 能力，以及可复用的 Skill 方法论。**

### 让 AI 开发更有效

我深度使用 Codex 和 DeepSeek Harness，探索需求拆解、设计评审、代码实现、独立验收和 PR 跟进怎样形成完整的开发过程。

我会比较不同模型的表现和成本，也在做工作树插件和协作技能，让多个开发任务更容易隔离、交接和验收。准确性优先，成本与响应速度一起衡量。

## 我的做事方式

- **先说清最终体验。** 我经常先描述用户应该看到什么、能做什么，再把需求拆开。开始实现前，我喜欢先确认双方理解的是同一件事。
- **遇到不懂的地方就追问。** 架构怎样运行、接口从哪取数据、数字怎样算出来，我希望能把它们讲明白。
- **让复杂度有理由。** 优先利用已有能力，先做一个能用的版本；新增抽象、流程和组件，应当解决眼前的问题。
- **用实际结果验收。** 我重视真实接口、真实模型和浏览器中的完整操作，尤其在意异常情况、前后端联调和部署后的回归。
- **把界面当作功能的一部分。** 布局、动画、反馈和操作路径都会影响体验。我会在意一张卡片怎样出现、抽奖怎样停下来、悬浮窗是否方便使用。
- **方向确认后持续推进。** 常规实现可以自主完成，影响业务口径、数据或整体结构的决定先对齐。做完实现，也要处理验证、文档和收尾。
